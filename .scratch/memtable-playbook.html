Memtable Playbook

Hints and generic code shapes for implementing src/memtable.cpp. The patterns use placeholder names on purpose — translate them into your actual container_, Entry, and field names rather than pasting them in as-is.

0 / 0 checked

Two decisions this file forces you to make

  • Overwrite accounting — when Put replaces an existing key's value, does size_bytes_ just add the new size on top (simple, slightly over-counts) or look up the old entry first and apply a delta?
  • Tombstone visibility — does Get return the raw tombstoned Entry (every caller must remember to check is_tombstone) or collapse it to std::nullopt so "deleted" and "never existed" look identical from the outside?
1

Put

void Put(const std::string& key, const std::string& value, uint64_t seq)
  • table_[key] = Entry{value, seq, false} handles insert and overwrite in one line — std::map::operator[] already does the "exists? update : create" branch for you.
  • Resolve the overwrite-accounting decision from above here, in the one place size_bytes_ changes for puts.
  • Nothing in this function checks that seq is newer than what's already stored for the key. That's fine while your only caller applies records in order — just know it's an assumption, not something the code enforces.

General shape — translate the names to yours

// insert-or-update in one line: operator[] creates if absent, overwrites if present
container_[key] = RecordType{ value, seq, /* deletedFlag */ false };

// running-size accumulator — pick overwrite semantics deliberately
running_bytes_ += key.size() + value.size();
2

Delete

void Delete(const std::string& key, uint64_t seq)
  • Same shape as Put, but store Entry{"", seq, true}.
  • Never call table_.erase(key). A real erase would let a later flush resurrect an older on-disk value for this key once SSTables exist — that's the entire reason is_tombstone is a field instead of just deleting the entry.
  • Decide whether a tombstone still counts toward size_bytes_. It occupies a map node and the key bytes even with no value.

General shape — translate the names to yours

// tombstone: overwrite with a marker record, never erase()
container_[key] = RecordType{ /* empty payload */ "", seq, /* deletedFlag */ true };
3

Get

std::optional<Entry> Get(const std::string& key) const
  • Use table_.find(key), not table_[key] — operator[] is non-const and would insert a default entry for a missing key. It won't even compile here, which is a useful forcing function.
  • Apply the tombstone-visibility decision from above: if it->second.is_tombstone, return std::nullopt rather than the entry, so "deleted" and "missing" are indistinguishable to every caller from here on.

General shape — translate the names to yours

// const-safe lookup: find(), never operator[], on a const method
auto it = container_.find(key);
if (it == container_.end() || it->second.deletedFlag) {
    return std::nullopt;
}
return it->second;

getSize

size_t getSize() const
  • Just returns size_bytes_.
  • The invariant to protect: size_bytes_ may only change inside Put/Delete. If any later code touches table_ directly, the count silently drifts from reality — and this is the number week 2's flush threshold will trust.

General shape — translate the names to yours

// just exposes the running total — no computation happens here
size_t ClassName::GetSize() const {
    return running_bytes_;
}
5

begin / end

std::map<std::string, Entry>::const_iterator begin() const / end() const
  • One-line forwards: return table_.begin(); / return table_.end();. The type work is already done in the header.
  • These wrappers exist only to keep table_ private — callers can iterate sorted entries without being able to mutate the map out from under your size accounting.

General shape — translate the names to yours

// forward to the backing container's own iterators — no logic of your own
ContainerType::const_iterator ClassName::begin() const { return container_.begin(); }
ContainerType::const_iterator ClassName::end()   const { return container_.end();   }
✓

Before you touch the WAL

  • Write tests/memtable_test.cpp now — this is the cheapest point to catch a tombstone or size bug, before it's buried under WAL and facade code.
  • Test: Put → Delete → Get reflects your tombstone-visibility decision consistently.
  • Test: iterating begin()/end() yields sorted key order — free with std::map, but lock it in with a test now in case the backing structure ever changes.
  • Test: getSize() increases after a Put and behaves the way you decided for deletes.
